## 2026-10-11 · brainstorm 定稿 · Phase B spec 文档

- **关键原话**：
  - 用户指定 Phase B 完成标准为「链路跑通 + 记录留痕 + 状态归档，三条同时成立」
  - 用户明确「三层留痕，不是一层，轨迹表兜不住审计，但也不该把所有东西都塞进 EvidenceStore」
  - 用户明确「证据 ID 是准入门槛，置信度只是排序信号，两件事都不许退让，但它们管的不是同一件事」
  - 用户明确「复检范围是一个必须显式声明、且被断言校验的参数，不是固定 3 个 SN，也不是默认整批 10 个。默认取最小受影响集，但『扩大』必须能发生且被记录」
  - 用户明确「卡在原地。断言失败不改变批次状态，状态机里根本没有『断言失败』这条边」
  - 用户明确「只生成处置报告就够，拒因不用单独处理」（`rejected` 终态只挂处置报告）
  - 用户明确「自动的，报告生成完成即归档」（批次终态 `archived` 自动触发，非手动 API）
- **关键产出**：
  - spec 文档：`docs/superpowers/specs/2026-10-11-phaseb-incident-report-design.md`
  - 锁定决策 D1–D7（用户拍板）+ L1/L1a/L2/L3/D5a/D6a/D8–D14（我拍板，* 标记，待评审确认；复审后 L1/L1a/L2/L3 升级为「用户确认」，见下方复核记录）
  - Phase B 交付物清单：异常 API / 归因 Skill / 复检 API / 放行 API / 报告 Skill + 自动归档 / LangGraph `incident_subgraph` / 4 静态页 / 3 个新增夹具文件
  - 三层留痕分工：`agent_task_traces`（轨迹）/ `evidence`（证据）/ `reports`（报告），不互相替代
- **拒绝与纠偏**：
