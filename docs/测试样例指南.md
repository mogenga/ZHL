# 质慧链 · 测试样例指南

> 面向演示与验收测试：告诉你在每个环节**输入什么、预期看到什么**。
> 界面入口：工作台 → 批次 → 数据入场「提交送检数据」。

---

## 0. 现成 CSV 样例文件（docs/test/csv/）

| 文件 | 内容 | 用法 |
|---|---|---|
| `csv-01-normal.csv` | 5 行全合格（SN-OK-001~005，数值围绕标称自然分布） | 批次数量建 **5** → 判定+抽样全过，直达放行；演示「正常生产」 |
| `csv-02-boundary.csv` | 8 行贴近容差边界但留有余量（SN-SAFE-001~008，全合格） | 批次数量建 **8** → 全过直达放行；边界感演示（如 pmax 535/564，距容差界 1.5~2.5W） |
| `csv-03-errors.csv` | 6 行，仅 `SN-MILD-006` 一行 pmax 轻微超差（530.0），其余全合格 | 批次数量建 **6** → 单因子温和失败 → 自动隔离 + 建 rule_fail 异常 → 走完整异常闭环 |

复检数据（csv-03 走闭环时用）：
- 复检弹窗 SN 选 **SN-MILD-006**（被处置的不合格件，别选合格件）
- 数值填：`550.0, 25.0, 10.5, 48.0, 40.0, 13.0, 0.80`（全取合格区间中位值，稳过）
- 范围选**最小集**，「范围组件条码」留空（后端自动按异常 SN 填）
- 复检通过 → 勾「确认关闭异常」→ 批次转待放行 → 放行 → 报告

通用注意：
- 用「从 CSV 导入」选文件（自带表头识别，秒级）；或粘贴数据行（**不含表头**，表头会报「非数字」）
- 三份样例都建议走「已结构化数据」/CSV 导入（结果确定）；「原始单据（AI 抽取）」走真模型约 10 秒/行，只在演示 AI 读单据时用
- 判定是逐行全检，抽样只是额外 AQL 检查，不会有行被漏判

## 1. 检测数据格式（9 列，每行一条）

```
SN, pmax, temp, isc, voc, vm, im, ff, 外观
```

| 列 | 含义 | 合格区间（JH-550W 演示规则） |
|---|---|---|
| SN | 组件条码 | 本批次内唯一；跨批次重复会触发冲突 |
| pmax | 功率 (W) | 533.5 ~ 566.5（标称 550，容差 ±3%） |
| temp | 温度 (℃) | 22.5 ~ 27.5（标称 25，±10%） |
| isc | 短路电流 (A) | 9.98 ~ 11.03（标称 10.5，±5%） |
| voc | 开路电压 (V) | 45.6 ~ 50.4（标称 48，±5%） |
| vm | 工作电压 (V) | 38.0 ~ 42.0（标称 40，±5%） |
| im | 工作电流 (A) | 12.35 ~ 13.65（标称 13，±5%） |
| ff | 填充因子 | 0.784 ~ 0.816（标称 0.80，±2%） |
| 外观 | 目检结果 | 只能填 `pass` 或 `fail` |

**任一数值参数出区间、或外观为 fail → 该组件判定不合格。**

其他要求：
- 每行恰好 9 列，英文或中文逗号均可，行内多余空格会自动去除
- 数值列必须是数字；外观列必须是 pass/fail
- 同一批次内 SN 不可重复（系统约束 D17，重复行会被拒绝）
- 「人工覆盖字段」留空即可（用于 AI 抽取值的人工修正，只留痕不覆盖实测值）

## 2. 三条完整测试路径

### 路径一 · 全流程成功（无异常直达放行）

1. 新建批次：数量 **2**，JH-550W
2. 数据入场粘贴：

```
SN-OK-001,550.0,25.0,10.5,48.0,40.0,13.0,0.80,pass
SN-OK-002,551.2,24.8,10.6,48.1,40.1,13.1,0.81,pass
```

3. 预期：判定全 Pass → 抽样 Pass → 批次直达「待放行」→ 放行 → 生成报告

### 路径二 · 异常闭环成功（隔离 → 处置 → 复检 → 关闭 → 放行）

1. 新建批次：数量 **2**
2. 数据入场粘贴（第 2 行 pmax 超差）：

```
SN-FLOW-001,550.0,25.0,10.5,48.0,40.0,13.0,0.80,pass
SN-FLOW-002,470.0,25.0,10.5,47.2,40.0,12.4,0.74,fail
```

3. 预期：SN-FLOW-002 判定不合格 → 批次隔离 + **自动创建异常**（无需手动建）
4. 异常处置节点按序操作（⚠️ 每步都必做，漏填会卡在关闭环节）：

| 异常状态 | 操作 | 填写内容 |
|---|---|---|
| 新建 | 隔离异常 | — |
| 已隔离 | AI 归因 → 采纳一条假设 | — |
| 已隔离 | 指派责任人 | 责任人 `张工`；期限未来时间；**第 3 栏「临时措施」必填**：`立即隔离受影响SN并通知产线排查` |
| 已指派 | 填报整改措施 | 根因 `焊接功率偏移`；纠正措施 `返工重测并更换焊带` |

5. 复检节点录入复检数据（范围选 minimal，SN 填不合格件）：

```
SN-FLOW-002,550.5,25.0,10.5,48.0,40.0,13.0,0.80,pass
```

6. 预期：复检通过（CAPA 自动置位）→ 确认关闭异常 → 批次转待放行 → 放行 → 报告

### 路径三 · 复检失败 → 拒绝

1. 新建批次：数量 **2**，入场数据：

```
SN-REJ-001,550.0,25.0,10.5,48.0,40.0,13.0,0.80,pass
SN-REJ-002,520.0,25.0,10.5,48.0,40.0,13.0,0.80,fail
```

2. 异常处置：同路径二第 4 步（隔离 → 归因采纳 → 指派含临时措施 → 填整改措施）
3. 复检录入**仍不合格**的数据：

```
SN-REJ-002,518.0,25.0,10.5,48.0,40.0,13.0,0.79,fail
```

4. 预期：异常与批次转 **rejected**（终态归档），报告页只能生成异常处置报告

## 3. 边界与防御场景

| # | 场景 | 输入/操作 | 预期结果 |
|---|---|---|---|
| 1 | 低置信度人工确认 | 入场数据含 `SN-LOW-001,...` | 入场中断，需人工确认/拒绝 |
| 2 | 跨批次 SN 冲突 | 新批次复用已入场 SN（如 `SN-OK-001`） | 自动建 `data_consistency` 异常（critical） |
| 3 | 同批重复 SN | 同一 SN 粘贴两行 | 提交被拒（EXCLUDE 约束） |
| 4 | 列数错误 | 某行只有 8 列 | 前端提示「应为 9 列」 |
| 5 | 数值非法 | pmax 填 `abc` | 前端提示「第 X 列非数字」 |
| 6 | 外观非法 | 外观填 `ok` | 前端提示「外观须为 pass/fail」 |
| 7 | 容差边界（合格） | pmax = `566.5` 或 `533.5` | 恰好压线 → 合格 |
| 8 | 容差边界（不合格） | pmax = `566.6` 或 `533.4` | 超差 → 不合格 |
| 9 | 人工建异常 | 已隔离批次点「再建一条异常」，类型选「外观人工触发」 | 两条异常**全部关闭**后批次才能放行 |
| 10 | 放行断言拦截 | 存在未关闭异常时点放行 | 断言失败、状态不变、可重试 |
| 11 | 已发布规则防篡改 | 规则版本页修改已发布版本字段 | 触发器拒绝（D6 红线） |

## 4. 各节点操作速查（易漏项已标红）

| 批次状态 | 下一步操作 | 易漏点 |
|---|---|---|
| 待入场 | 提交送检数据（本页 §1 格式） | — |
| 待判定 | 自动流转，无需操作 | — |
| 已隔离 | 异常处置：隔离 → 归因 → 指派 → 整改措施 | ⚠️ 指派弹窗第 3 栏「临时措施」是可选项但关闭时硬性要求 |
| 处置中 | 填报整改措施 | 根因 + 纠正措施都必填 |
| 待复检 | 录入复检数据 → 确认关闭异常 | 复检通过≠自动关闭，关闭是人工签署动作 |
| 待放行 | 放行（7 项断言） | 有未关闭异常时放行会被拦截 |
| 已放行/已拒绝 | 生成报告 | — |

## 5. 常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| 关闭条件尚未满足：未填报临时措施 | 指派时第 3 栏留空 | 联系管理员补库，或重建演示批次（下次指派时填上） |
| 判定失败后批次隔离才能创建异常 | 批次还没到隔离态 | 先让判定流程跑完 |
| 请先隔离该异常 | 异常还是「新建」态就点指派 | 先点「隔离异常」 |
| 部分组件条码不在本批次内 | 创建异常时 SN 拼错 | 核对 SN |
| 批次已归档，内容只读 | 终态批次 | 新建批次继续测试 |
